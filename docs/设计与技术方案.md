## 1. 素材转换：Unity → Godot 到底难在哪

### 1.1 先看清 `.unitypackage` 是什么

它本质是 **gzip 压缩的 tar**，每个资源一个 GUID 目录：

```
<guid>/asset        <- 真正的二进制（.fbx / .png / .mat / .prefab）
<guid>/pathname     <- 原始工程路径（注意：文件里带 "\n<size>" 尾巴，要只取第一行）
<guid>/asset.meta   <- 导入设置
```

`pathname` 这一步很关键 —— 不解析它就只能拿到一堆 GUID，没法还原目录结构。
（浮浮酱第一次就是被 `pathname` 尾部那行 `\n00` 坑到，`splitext` 全对不上，解包出 0 个文件。）

### 1.2 为什么不用"Unity → FBX → 直接丢进 Godot"

Godot 4 不原生支持 `.fbx`，官方推荐 glTF。所以链路是：

```
.unitypackage
   └─ 解包 ──> Models/*.fbx + Textures/*.png + Materials/*.mat + Prefabs/*.prefab
        └─ Blender 5.2 无头批处理 ──> assets/models/<分类>/<名字>.glb
```

Blender 负责三件事：FBX 解析、坐标轴转换（Y-up）、材质名归一。

### 1.3 两个必须踩过的坑（都已解决）

**坑 1：贴图不能内嵌进 GLB。**
POLYGON 的 400+ 个模型共用同一张 2048 图集。如果每个 GLB 都内嵌贴图，
显存里会出现几百份一模一样的图集（每份 4MB × 400 ≈ 1.6GB）。

做法：GLB **只导几何 + 材质名**（`export_image_format='NONE'`），
Godot 侧由 `AssetLib` 按材质名查表，挂**共享** `StandardMaterial3D`。
结果是 24 张图集服务全部 756 个模型。

**坑 2：GLB 根节点上挂着 0.01 缩放。**
Synty 的 FBX 网格数据是厘米，单位换算挂在根节点。
正常实例化没问题，但**一旦把 mesh 抽出来做 MultiMesh（植被），这层缩放就丢了** ——
树会变成 400 米高，把整个画面糊成黑屏。

做法：`AssetLib.extract_mesh_data()` 返回 `{mesh, transform}`，MultiMesh 实例变换里把 `base_xf` 乘回去。

**坑 3：朝向不能用 `basis.z` 判断。**
GLB 根节点上还带一层 **90° 的 X 旋转**（Blender 的 Z-up → glTF 的 Y-up 转换写在了节点上），
所以任何实例的 `basis.z` 永远指向世界 -Y（朝下），拿它当"长轴"必然得出错误结论。
判断朝向只能量**世界包围盒**，或者记住"本地 Y 才是水平长轴"。

**坑 5：第一人称的枪不能按"场景物体"摆。**
枪的模型原点在**枪身中段**，枪管朝 **+Z**（朝向玩家）。三种错法都试过：
`yaw=0` 枪口顶在脸上、`yaw=90` 枪横在镜头前（这两个都会把屏幕糊成"黑屏"）、
`yaw=180` 才是枪口朝前。正确参数：`rotation.y = 180°`、位置 `(0.28, -0.26, -0.58)`、缩放 `0.70`。

> 教训：判断枪口朝哪，**不要看渲染图猜**，也别用 `basis.z` 之类的轴判断。
> 用 `tools/fps_wep_probe.tscn` 把 0/90/180/270 四个角度各拍一张，一眼就能选。

**坑 4：碰撞体不能挂在 GLB 根节点下。**
根节点带 0.01 缩放，碰撞盒挂上去会被一起缩成 1cm。
`AssetLib.spawn()` 因此返回一层**包装节点**：模型实例和碰撞体都是它的子节点，互不干扰。

### 1.4 材质 → 贴图的对应关系怎么来的

不靠命名猜测，走确定性链路：

```
prefab 里的 m_Mesh.guid  ->  fbx 路径
prefab 里的 m_Materials.guid  ->  .mat 路径
.mat 里的 _MainTex.guid  ->  贴图路径
```

产出 `_build/asset_index.json`（1486 个模型 → 63 个材质 → 全部解析到贴图）。

Blender 里把每个模型的非玻璃材质统一重命名成它自己的主材质名
（这样 Godot 侧"按名字查图集"就行），玻璃统一叫 `__glass__`。


## 2. BRM 5 拆了什么，我们取了哪些

参考对象：**Blackhawk Rescue Mission 5**（Roblox，PLATINUM FIVE）。
它是一个以白令海峡岛屿 **Ronograd** 为舞台的开放世界战术射击，核心是
"从 FOB 出发 → 打据点/做任务 → 带回战利品"的循环。

| BRM5 的机制 | 我们的实现 | 取舍说明 |
|---|---|---|
| 开放岛屿 + 多据点 | 1600m × 1600m 程序化岛，8 个手工布局据点 | 地形用噪声 + 据点平台整平，每次开图不同 |
| 两大阵营（RLF / Patriots） | OPFOR（武装分子）/ BLUFOR（玩家+友军） | 保留红蓝对立 |
| 玩家互相对抗 | **RIVAL 第三方 AI 小队**（敌对所有人） | 单机没有真人，用"另一队玩家"的替身制造 PvP 压力；接口留给后续联机 |
| 医疗：绷带/敷料/维生素 | 同款三件套，且**绷带↔敷料有先后加成**（+15） | 复刻了原版"先敷料后绷带"的小技巧 |
| 倒地 + 失血 + 拖拽救援 | 倒地 60s、按住空格延缓失血、队友可救起 | 拖拽暂未做 |
| 爆头/狙击秒杀 | 头部命中 ×2.6 伤害 | 简化为一击重伤而非必死 |
| FOB / 军械库 | 铁砧前线基地：直升机坪、指挥帐篷、军械柜、医疗床 | 军械库改枪暂未做 |

## 3. 玩法循环

```
铁砧基地落地（友军 3 人跟随）
   ↓
接受任务：夺取 <随机敌方据点>
   ↓
横穿岛屿 → 遭遇 OPFOR 巡逻队 / RIVAL 小队
   ↓
进入据点圆圈 → 清掉守军 → 控制进度 0→100%
   ↓
任务转为「撤离」→ 按 G 呼叫直升机 → 14s 后降落 → 按 F 登机
   ↓
结算：信用点 + 经验 + 击杀数；阵亡则损失 25% 信用点
```

据点会每 45 秒补一次人（上限 34），逼玩家不能无限磨。

### 几个设计决定

**不用 NavigationAgent3D。**
1600m 地形上实时烘焙导航网格太贵。改用"前向 1.8m 探障 + 撞墙侧滑"的转向，
配合据点周围的巡逻点，行为已经够可信，而且完全可预测、可测试。

**HUD 全部用 `_draw` 画。**
少一个 `.tscn`，改布局只改代码，也不会被编辑器改坏。

**角色用程序化骨骼动画，不依赖动画片段。**
POLYGON 角色只带一套静态姿势（没有 walk/idle 片段），但骨架是完整的 50 根骨。
`CharacterRig` 直接驱动其中 15 根关键骨：大腿前后摆、膝盖单向弯、躯干前倾、头部朝向、手臂下垂/举枪。

难点不在数学，在**坐标系**：
- 每根骨骼的局部轴都不一样，还有整体 90°X 的 Z-up 转换 → 不能猜轴。
  统一用"场景空间轴"表达意图，再换算到骨骼局部：
  `bone_axis = (skeleton_global_basis * bone_global_pose.basis).inverse() * scene_axis`
- **GLB 的默认 pose 不是单位四元数**（Root 90°、Spine 180°…）。
  直接把骨骼设成 identity 等于把角色掰平（第一次就是这么把三个人拍成趴地上的）。
  正确做法：记下默认姿势，增量叠在它上面：`pose = base * delta`。

枪挂在右手骨骼上（`BoneAttachment3D`）。注意骨骼空间是厘米，枪要放大 100 倍才回到米。

**围墙按模型真实尺寸自动排段。**
`SM_Prop_Barrier_Tall_Group_01` 是 0.82 × 3.26 × **5.17**（长轴在 Z），
`SM_Prop_Barrier_Base_Row_01` 是 **3.42** × 1.05 × 1.22（长轴在 X）。
所以 `_wall_place()` 从 `model_meta` 读尺寸，自动算段数、自动判断要不要转 90°，
调用方只给起点和终点。硬编码间距（原来写的 7m）必然漏风。

**地形先压平再建网格。**
顺序是 `噪声 → 据点平台整平 → 生成网格 → 生成碰撞`。
如果反过来，建筑会浮空或陷进地里。

## 5.5 AI 小队系统

单兵再聪明，一群人也只会各打各的。`src/ai/squad.gd` 把士兵编成班组，解决三件事：

### ① 情报共享
任何一个成员看见敌人，就调用 `report_contact()` 把**接触点**写进小队黑板。
其余成员哪怕被墙挡住、没有视野，也会把 `_last_seen` 设成这个点并转入 SEARCH 摸过去。
> 效果：玩家打一枪，整班都会朝这个方向压过来，而不是只有开枪那一个人追。

### ② 交替掩护（bounding overwatch）
接触后先稳 1.8 秒（CONTACT），然后进 ASSAULT：
按成员序号分成**两个火力组**，每 4.5 秒轮换一次 ——
- 一组 `advance`：绕到接触点侧翼 15~21 米处，**跑动中不射击**
- 一组 `hold`：站定输出，射速 ×1.43、散布 ×1.35（压制射击）

> "跃进组不射击"这条纪律不只是拟真：它还顺便解决了"全队同时开火把玩家瞬秒"的平衡问题。

### ③ 士气与溃退
每阵亡一人，士气 -0.22；士气 < 0.35 或只剩 1 人 → BROKEN，
全队丢掉战术动作、朝集结点跑，且不再主动交火。

### 班组角色
| 角色 | 修正 |
|---|---|
| 队长 leader | 命中 +0.08、生命 +25；阵亡后自动由下一名队员接替 |
| 机枪手 support | 伤害 +4、射速更快、命中 -0.05 |
| 精确射手 marksman | 命中 +0.16、射程 +70、观察距离 +30、射速变慢 |
| 步枪手 rifleman | 基准 |

### 编成
- 每个敌方据点 = 一个班（3~7 人，按玩家等级浮动）
- 玩家身边 = 一个友军班（跟随玩家，同样会报点、会交替掩护）
- 第三方势力 = 两个 3 人小队，四处游荡

## 8. 已知限制 / 下一步

1. **没有联机**。当前 PvP 压力由 RIVAL AI 模拟。要真联机，`Soldier` 与 `Player` 的
   伤害接口（`take_damage`）已经统一，接 ENet + 状态同步即可。
2. **动画是程序化的**，能走能举枪，但没有上下半身分离、没有换弹/受击动作。
   接 Mixamo 的 idle/walk/aim 三套片段会更好，`CharacterRig` 的接口不用改。
3. **据点布局是硬编码的**。想更耐玩应该做成数据驱动（JSON 描述布局），支持随机化。
4. **载具不能开**。机场的喷气机、基地的卡车目前只是场景道具。
5. **枪械改装未做**。素材里有完整的配件库（`SM_Wep_Mod_*`），已转换但未使用。
6. **地形 8.3m 一格**。近看会有折角，若要更细腻可提到 257 格（代价是顶点数 ×1.8）。
