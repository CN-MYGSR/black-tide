### 踩到的坑（都修了）
1. `.unitypackage` 的 `pathname` 文件尾部有 `\n<size>`，不取第一行会导致 splitext 全对不上 → 解包 0 个文件。
2. 贴图内嵌 GLB 会让同一张图集在显存里复制几百份 → 改成 GLB 只带材质名 + Godot 侧共享材质。
3. **MultiMesh 丢缩放**：Synty FBX 网格是厘米，0.01 缩放挂在 GLB 根节点；
   直接抽 mesh 做 MultiMesh → 树变 400 米高，整屏黑。修法：`extract_mesh_data()` 返回 transform 并乘回去。
4. **据点模型坐标叠加两次**：`_node.position = _center` 之后又传世界坐标给 `spawn()`（它设的是 local position）→ 所有模型飞到岛外。
   自检里补了"模型有没有跑出据点"这条断言才抓住。
5. AI 打不中人：散布公式太宽（6.5°→3.6°）+ 测试时敌人背对玩家（FOV 110° 看不到背后）。

## 追加：围墙朝向返工（主人指出 02_fob_air.png）

主人一眼看出 FOB 围墙"想围住但方向错了 90 度、长度也不够"。

根因两条：
1. `SM_Prop_Barrier_Tall_01` 是 0.7 宽 × 1.72 **长（长轴在 Z）**，旧代码按"长轴在 X"摆，
   且间距硬编码 7m（单块才 1.72m）→ 既转错又漏风。
2. **`basis.z` 不能用来判断朝向**：GLB 根节点带 90°X 旋转（Z-up→Y-up 写在节点上），
   任何实例的 basis.z 永远指向世界 -Y。第一版断言用了它，44 段全判错——断言本身也错了。
   正确做法：量世界包围盒（`global_transform * get_aabb()` 合并）。

顺带补了**碰撞**：原来所有 POI 模型都没有碰撞，玩家能直接穿墙，"围住"是假的。
`AssetLib.spawn()` 改成返回**包装节点**（模型 + 可选 BoxShape3D 碰撞体），
因为 GLB 根节点带 0.01 缩放，碰撞体直接挂上去会缩成 1cm。

新增断言：围墙段数 / 每段长轴与所在边平行 / 每边首尾相接（最大间隔 5.2m）/ 射线被墙挡住。
自检 38 → **43 项**，集成 17 项不变，全绿。

## 追加：黑屏 + 玩家模型/骨骼动画

主人报"黑屏"两次，根因是**第一人称的枪贴在镜头前**：
枪的模型原点在枪身中段、枪管朝 **+X**，旧参数 `rotation.y=180°` + `z=-0.44` + 缩放 0.95，
等于把一把 1 米长的枪横在镜头前 → 整个视野被枪身糊住。
最终正确值：`rotation.y=180°`（枪管模型朝 +Z，要翻过来）、位置 `(0.28,-0.26,-0.58)`、缩放 0.70。
（0 会让枪口顶脸、90 会让枪横着 —— 三个角度都实测拍过。）
**教训：之前只拍过自由相机，从没拍过玩家第一视角，所以这个 bug 一直没暴露。**

同时补完骨骼动画（`src/ai/character_rig.gd`）：
- 15 根关键骨：大腿摆 / 膝盖单向弯 / 躯干前倾 / 头朝向 / 手臂下垂与举枪。
- **GLB 默认 pose 不是单位四元数**（Root 90°、Spine 180°），设 identity 会把角色掰平 →
  必须记下 `base`，增量叠加 `pose = base * delta`。
- 场景轴→骨骼局部轴换算：`(skel.global_basis * bone_global_pose.basis).inverse() * axis`。
- 枪用 `BoneAttachment3D` 挂右手骨，**骨骼空间是厘米，要 ×100**。
- 玩家也接上了：`body_rig` + 第三人称手里的枪，V 键切换。

自检 43 → **46 项**（新增：骨骼已绑定 / 动画真的驱动骨骼 / 摆腿幅度可见），集成 17 项，全绿。
